Extensibility & Ecosystem

Everything so far has been built-in Kubernetes. This page covers how the API and its patterns get extended, and how the ecosystem packages and customizes what you deploy.

CRDs: extending the API itself

A CRD lets you define your own object type — say, PostgresCluster — that the API server will happily store and serve. On its own, a CRD is inert: creating an instance of it is barely more than writing a row in a database. Nothing happens until something is watching it.

Operators: the reconciliation loop, for your own resource

An Operator is a CRD plus a controller that watches it and reconciles reality to match — the exact same loop from Architecture's reconciliation-loop explainer, just applied to a resource you invented instead of a built-in one like ReplicaSet.

Helm vs. Kustomize vs. raw manifests

ApproachWhat it's for
Raw manifestsPlain YAML, applied directly — full control, but repeats itself across environments
KustomizeEnvironment-specific tweaks to existing manifests without duplicating whole files
HelmPackaging and distributing a whole application, with configurable values and a release/rollback lifecycle

These solve overlapping but different problems — many real setups use both: Helm to install a chart, Kustomize to patch the result for a specific environment.

Common gotchas

  • A CRD without a controller does nothing. Creating the object is barely more than writing a database row — something needs to be watching and reconciling it, or it's inert.
  • Helm charts can run arbitrary logic via hooks. Installing a chart from an untrusted source can execute code in your cluster, not just apply YAML — treat it like installing software, not configuration.
  • Operators often carry broad RBAC permissions. To do their job (managing their resource across a namespace or cluster) they typically need wide-reaching access — a buggy or compromised Operator has a correspondingly large blast radius. See Policy & Security.
  • Kustomize and Helm aren't really competitors. One customizes existing YAML per environment; the other packages and distributes a whole application — plenty of real setups use both together.
