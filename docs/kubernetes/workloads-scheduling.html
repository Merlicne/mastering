Taints, tolerations, and affinity point in different directions

MechanismLives onEffect
Taint + tolerationNode / PodRepels — permits scheduling there, doesn't attract anything
Node affinityPodAttracts toward nodes with matching labels
Pod affinity / anti-affinityPodAttracts or repels relative to other Pods, e.g. spreading replicas across nodes

Resource requests and limits matter here too: requests are what the filter stage checks against available capacity; limits are enforced later, while the container is actually running.

Common gotchas

  • A toleration doesn't attract a Pod to a tainted node. It only permits scheduling there — if you actually want a Pod to prefer that node, you still need affinity too.
  • Exceeding a CPU limit throttles; exceeding a memory limit kills. This asymmetry catches people who assume both resource types behave the same way under pressure.
  • Deployments don't guarantee ordering; StatefulSets do. Swapping one for the other because "it's basically the same" breaks anything relying on stable per-replica identity or ordered startup/shutdown.
  • DaemonSets don't compete for "the best" node. They intentionally bypass normal resource-based scoring — the point is to run on every matching node, not the optimal one.
