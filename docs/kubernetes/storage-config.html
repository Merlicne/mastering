Storage & Configuration

Containers are meant to be disposable — so anything that needs to survive a restart, a reschedule, or a config change needs its own Kubernetes objects rather than living inside the container image.

Volumes: storage tied to a Pod's lifetime

A plain Volume like emptyDir exists only as long as the Pod does — useful scratch space, or a way for containers in the same Pod to share files, but gone the moment the Pod is rescheduled elsewhere.

PersistentVolume & PersistentVolumeClaim: decoupling storage from Pods

A PersistentVolume (PV) is real storage with its own lifecycle. A PersistentVolumeClaim (PVC) is a request for storage matching certain criteria — size, access mode, class — without needing to know which specific PV will satisfy it. This is the same decoupling idea as a Service hiding which exact Pod answers a request, just applied to storage instead of networking.

StorageClass: dynamic provisioning

Instead of an admin pre-creating PVs by hand, a PVC can reference a StorageClass, and its provisioner creates a matching PV automatically. Each PV also has a reclaim policy — Retain keeps the data around after the PVC is gone; Delete destroys it too.

ConfigMaps & Secrets

A ConfigMap holds ordinary config data. A Secret holds the same shape of data, but for sensitive values — and access to it is restricted via RBAC.

Common gotchas

  • Secrets are base64, not encrypted, by default. Anyone who can read the Secret object — or an unencrypted etcd backup — can trivially decode it. Base64 is an encoding, not a cipher; real protection needs encryption at rest configured separately.
  • Dynamically provisioned volumes often default to a Delete reclaim policy. Deleting the PVC can silently delete the underlying data too — unlike many hand-provisioned PVs, which commonly default to Retain.
  • ConfigMap/Secret changes don't automatically restart Pods. A mounted file may update eventually; env-var-injected values are frozen at container start. Teams often add a checksum annotation or a tool like Reloader to force a rollout when config actually changes.
  • emptyDir doesn't survive eviction or rescheduling. It's tied to the Pod's lifetime on that specific node — use a PVC for anything that needs to outlive the Pod itself.
