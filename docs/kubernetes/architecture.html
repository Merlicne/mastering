Architecture & Control Plane

A Kubernetes cluster splits cleanly into two halves: a control plane that makes decisions, and worker nodes that run your actual workloads. Nothing on this page runs your application — it's the machinery that decides where and how it runs.

Cluster topology

Production clusters run the control plane on multiple machines for high availability: several API server replicas behind a load balancer, and an odd-numbered etcd cluster (3 or 5 members) so it can always establish a quorum even if a member is lost.

The reconciliation loop: Kubernetes' one big idea

Almost everything in Kubernetes, including every controller inside kube-controller-manager, runs the same loop: observe the actual state of the world, compare it to the desired state you declared, and take action to close the gap. Then do it again. This is what "declarative" actually means in practice — and it's the exact same pattern Operators use for custom resources, just applied to Kubernetes' own built-in objects first.

Crucially, this loop is level-triggered, not edge-triggered: a controller doesn't rely on receiving every single change event in order. It just needs to look at current state whenever it wakes up and re-derive what to do — so a missed event doesn't cause permanent drift, the next pass fixes it anyway.

Common gotchas

  • Losing etcd quorum doesn't just slow things down. With no majority available, no write can be committed at all — the cluster can go fully read-only, unable to schedule or change anything, even though existing pods keep running.
  • The API server needs redundancy too, not just etcd. Every other component depends on reaching it, so HA control planes run multiple API server replicas behind a load balancer, not only a multi-member etcd cluster.
  • Level-triggered reconciliation is a feature. It's tempting to think a controller needs perfect event delivery — it doesn't. It only needs to be able to look at the world and decide what to do, repeatedly.
  • Nothing should talk to etcd directly except the API server. If troubleshooting ever leads you toward querying etcd by hand, that's usually a sign something upstream is already misconfigured — the API server is deliberately the only sanctioned path in.
