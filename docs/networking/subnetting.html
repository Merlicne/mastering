Subnetting & IP Addressing

Enter an IPv4 address and a CIDR prefix to see exactly how the subnet mask splits it into a network portion and a host portion — updated live as you type or drag.

Subnetting matters because it lets one large address block be broken into smaller, independently routable pieces. A company with a /16 allocation (65,536 addresses) can hand a /24 (256 addresses) to each office instead of wasting the whole block on a single location.

Why subnet at all?

  • Smaller broadcast domains — every device in a subnet hears every broadcast; splitting a /16 into /24s means noisy traffic in one office doesn't flood every office.
  • Route summarization — a router can advertise one summarized route for an entire subnet instead of one route per host, keeping routing tables small.
  • Security boundaries — subnets are a natural place to enforce firewall rules, e.g. between a public-facing subnet and an internal database subnet.
  • Efficient allocation via VLSM — give each subnet only as many addresses as it actually needs.

Common gotchas

  • The network and broadcast addresses aren't usable hosts. That's why usable hosts = total addresses − 2 for anything /30 or larger.
  • /31 and /32 are special-cased by design. RFC 3021 lets a /31 use both of its addresses as real hosts on point-to-point links (e.g. router-to-router), and a /32 identifies a single host route with no subnet at all.
  • Classful addressing (Class A/B/C) is legacy. It hasn't determined real-world subnet sizes since the early 1990s — everything today is classless (CIDR), but the "Class" badge above is still useful shorthand for how big a block originally was.
  • A bigger prefix number means a smaller subnet. This trips up almost everyone at first: /24 (256 addresses) is much bigger than /30 (4 addresses) — the prefix counts fixed network bits, not host capacity.
