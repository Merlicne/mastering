DNS Resolution

The Domain Name System is what lets you type a name instead of memorizing an IP address. Follow what actually happens between typing a domain name and your browser getting an address to connect to — hop by hop.

Recursive vs. iterative queries

Your OS makes a recursive query to its configured resolver: "give me the final answer or an error, I don't want to talk to anyone else." The resolver then does the legwork by making a series of iterative queries to root, TLD, and authoritative servers, each of which just says "I don't know, but ask them" until it reaches an authoritative answer.

Common DNS record types

TypePurpose
AMaps a name to an IPv4 address. What this page's demo is simulating.
AAAAMaps a name to an IPv6 address.
CNAME"Canonical Name" — an alias pointing one name to another name, e.g. www.example.com → example.com, which is then looked up in turn.
MX"Mail Exchange" — which mail server should receive email for this domain, with a priority for failover.
TXTArbitrary text, commonly used for domain-ownership verification and email anti-spoofing records like SPF.
NS"Name Server" — declares which servers are authoritative for this domain. This is exactly what the TLD referral hands back in the walkthrough above.
SOA"Start of Authority" — metadata about the zone itself: the primary name server, an admin contact, and timers like the default TTL.

Common gotchas

  • Low TTLs aren't free. A short TTL makes DNS changes (like failing over to a new server) take effect faster, but it also means every resolver has to re-query more often — a tradeoff between agility and load.
  • "Propagation delay" is really just caching. There's no global push of DNS updates — every resolver only refreshes its own cached copy once that record's TTL expires, which is why the same change can appear at different times to different users.
  • NXDOMAIN gets cached too. If you query a typo'd domain, resolvers remember "this doesn't exist" for a while, so fixing a real typo and re-querying immediately can still show the old failure until that negative cache expires.
  • Plain DNS queries aren't encrypted by default. Anyone on the network path can see which domains you're resolving. DoH/DoT address this by encrypting the query itself.
